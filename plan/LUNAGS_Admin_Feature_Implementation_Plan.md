# LUNAGS 管理機能追加計画書
**— 管理者アカウント専用機能の設計と導入計画 —**

---

## 1. 概要と目的

本計画書は、**LUNAGS** において「管理者アカウント専用」となる3つの新機能を追加・実装するための包括的な設計計画書です。

### 目的
既存のシステムにおける「**管理者アカウント（恒久的な管理権限）**」と「**管理者モード（一時的な管理権限）**」の概念を厳密に分離し、セキュリティ境界を明確化した上で、以下の3領域を導入します。

- `account/users/`：ユーザー管理機能
- `management/logs/`：システム・操作ログ監視機能
- `management/analytics/`：利用状況・統計分析機能

---

## 2. 追加する機能の全体像

| パス | 機能名 | アクセス権限 | 概要 |
| :--- | :--- | :--- | :--- |
| `account/users/` | ユーザー管理 | **管理者アカウントのみ** | 登録ユーザー一覧・詳細の閲覧および基本状態の確認 |
| `management/logs/` | システム・操作ログ | **管理者アカウントのみ** | ログイン、権限変更、権限追加、Functionsエラーなどの監査ログ閲覧 |
| `management/analytics/` | LUNAGS分析 | **管理者アカウントのみ** | 利用者数、アクティブ率、機能利用状況などの統計可視化 |

---

## 3. 各機能の詳細設計

### 3.1 ユーザー管理 (`account/users/`)

#### 目的
LUNAGSに登録されている全ユーザー・アカウント情報を統括・確認する。

#### ディレクトリ構成
```text
account/
├─ admin/
│  ├─ admin.html
│  └─ admin.css
│
└─ users/
   ├─ users.html
   ├─ user.html
   └─ users.css
```

#### 主な表示・確認要素
- **ユーザー一覧 (`users.html`)**
  - ユーザー名
  - メールアドレス
  - UID（Firebase Auth）
  - ユーザーID（LUNAGS）
  - アカウント作成日時 / 最終ログイン日時
  - アカウント状態（有効 / 一時停止 など）
  - 管理者アカウントフラグ（`isAdminAccount`）
- **ユーザー詳細 (`user.html`)**
  - 基本プロフィール情報
  - アカウント状態および権限ステータス
  - 過去の登録・変更履歴

> **⚠️ 権限管理に関する注意事項**
> ユーザー管理画面において「無制約なデータ変更」を許可すると権限肥大化および破綻（権限設計の崩壊）を引き起こすリスクがあります。具体的な操作可能範囲は、既存の管理者設計およびセキュリティポリシーを厳密に照らし合わせた上で最小限に抑えます。

---

### 3.2 システム・操作ログ (`management/logs/`)

#### 目的
LUNAGSシステム内で発生した重要な監査・操作イベントを記録・追跡する。

#### ディレクトリ構成
```text
management/
├─ dashboard/
├─ logs/
│  ├─ logs.html
│  └─ logs.css
└─ analytics/
```

#### 記録・監査対象イベント
- **認証系**: ユーザーログイン / ログアウト
- **管理者権限系**: 管理者ログイン、管理者モードの開始 / 終了
- **アカウント・権限変更**: ユーザー情報の変更、権限の変更操作
- **システムイベント**: 重要な管理操作、Cloud Functionsエラー・例外

> **💡 既存システムとの連携**
> 管理者モードに関しては、既存の Functions 上にセッション・期限・履歴処理が存在するため、これら既存処理とのログ体系の統合を前提とします。

#### ログ表示フォーマット例
| 日時 | ユーザー | イベント | 対象 | 結果 |
| :--- | :--- | :--- | :--- | :--- |
| `2026/09/10 20:30` | User01 | 管理者モード開始 | セッション | 成功 |
| `2026/09/10 20:45` | User02 | アカウント情報変更 | Profile | 成功 |

> **🔒 改ざん防止**
> 蓄積されたログは原則として管理者を含むクライアント側からの直接的な変更・削除を禁止する改ざん不可設計を目指します。

---

### 3.3 LUNAGS分析 (`management/analytics/`)

#### 目的
LUNAGS全体の利用度合いや成長指標、システム状況の統計・トレンドを把握する。

#### ディレクトリ構成
```text
management/
├─ dashboard/
├─ logs/
└─ analytics/
   ├─ analytics.html
   └─ analytics.css
```

#### 分析指標（KPI）
- **ユーザーメトリクス**: 総ユーザー数、新規登録者数推移
- **アクティビティ**: 日別・月別アクティブユーザー数（DAU/MAU）、ログイン頻度
- **機能利用状況**: 各機能（ダッシュボード、タスク、ポスト等）の使用割合
- **期間フィルター**: 今日 / 今週 / 今月 / 過去30日間 などの切り替え

## 4. 権限設計とセキュリティアーキテクチャ

本計画における**最重要項目**です。既存の「管理者モード」と今回の「管理者アカウント」の権限境界を明確に区別します。

### 4.1 権限モデルの明確な分離

1. **管理者アカウント (`isAdminAccount = true`)**
   - 恒久的な最高権限を持つアカウント。
   - 今回追加する3機能（`users`, `logs`, `analytics`）を含む、すべての領域にアクセス可能。

2. **管理者モード (`isAdminAccount = false` / `adminMode = true`)**
   - 一般ユーザーが一時的な操作等のために付与された時限的・制限付き権限。
   - **今回追加する3機能には一切アクセス不可能**。

---

### 4.2 権限検証フロー（多層防御 / Zero Trust）

フロントエンドでの表示判定（UI非表示）のみに依存せず、**Cloud Functions（バックエンド）での二重検証**を徹底します。

```text
[ クライアント（ブラウザ） ]
         │
         │ 1. リクエスト送信 (ID Token 同封)
         ▼
[ Firebase Authentication ]
         │
         │ 2. Token 検証 & User ID 抽出
         ▼
[ Cloud Functions ]
         │
         │ 3. isAdminAccount フラグの厳格なチェック
         ▼
[ Firestore / Database ]
```

- Direct URL直打ち、または API の直接叩きに対しても、`isAdminAccount !== true` の場合は **HTTP 403 Forbidden** で確実に拒否します。
- これにより、管理者モードの権限境界の検証課題を解決します。

## 5. Cloud Functions の構造改革（リファクタリング）

現在 monolithic 化しつつある `functions/index.js` の肥大化を防ぐため、機能追加と並行してモジュール分割を実施します。

### 分割方針案
```text
functions/
├─ index.js          # エントリポイントおよび共通ミドルウェア
├─ auth/              # 認証・トークン検証処理
├─ admin/             # 管理者アカウント専用API
├─ users/             # ユーザー管理関連処理
├─ logs/              # ログ記録・取得処理
└─ analytics/         # 集計・分析API
```
*※ 実際のコード分割は、既存の `index.js` の処理内容を分析した上で安全に段階移行します。*

## 6. 実装ロードマップ

リスクを最小化するため、段階的（Phase別）に実装・検証を進めます。

```text
【Phase 1: 権限基盤】
  └── 管理者アカウント判定ロジックの実装
  └── Functions側の厳格な認証ミドルウェア構築
  └── 専用APIの保護設定

【Phase 2: Users（ユーザー管理）】
  └── account/users/ 画面実装
  └── ユーザー一覧・詳細API構築
  └── 制限付き管理操作の実装

【Phase 3: Logs（システムログ）】
  └── management/logs/ 画面実装
  └── 既存の管理者モード履歴・イベントログの統合

【Phase 4: Analytics（分析）】
  └── management/analytics/ 画面実装
  └── Firestore集計ロジックおよび統計グラフ表示

【Phase 5: 実機テスト & セキュリティ検証】
  └── 各権限（管理者アカウント / 管理者モード / 一般ユーザー）での動作検証
  └── 直アクセス・不正リクエスト拒否テスト
```
